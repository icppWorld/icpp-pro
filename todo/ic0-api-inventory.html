Fixed 2026-09-16

Broken bindings

removed

Five pre-Genesis “funds” declarations

msg_funds_availablemsg_funds_refundedmsg_funds_acceptcanister_balancecall_funds_add

These import names were removed from the interface spec years ago and are absent from the replica's whitelist — any canister calling one produced a wasm rejected at install time. They had zero call sites and are now deleted from ic0.h and the mock (ic0mock/ic0.h, ic0mock/ic0.cpp). Their 128-bit cycles replacements arrive in sequencing step 02.

fixed

ic0.h:84 merged call_perform and stable_size

uint32_t ic0_call_perform() WASM_SYMBOL_IMPORTED("ic0", "call_perform") uint32_t
    stable_size() WASM_SYMBOL_IMPORTED("ic0", "stable_size");

A missing semicolon merged two declarations, binding the second under the unprefixed name stable_size. Now split into two conventional declarations, with the symbol renamed to ic0_stable_size — matching the header's convention and the name the mock already used.

Bonus fix found during implementation: the mock header declared ic0_msg_reject_ic0_msg_size/copy (a botched rename) while the mock .cpp defined ic0_msg_reject_msg_size/copy; the header declarations now match the definitions.

Beyond raw bindings

The bigger Motoko-parity items

Largest gap · issue #21

Inter-canister calls

Raw call_new/call_perform plumbing and reply/reject/cleanup callback scaffolding exist, but there is no usable high-level async call API. Motoko's whole async/await model sits on this; C++ likely wants a coroutine- or callback-based IC_API layer.

Depends on call machinery

Composite queries

Needs both the canister_composite_query export naming and query-call plumbing layered on the call API.

Convenience layer

Certified variables

A hash-tree helper over certified_data_set plus the certificate reads, so query responses can carry verifiable certificates.

Branch: wasm64-and-wasmtime

Wasm64 / large heap

Motoko ships enhanced orthogonal persistence on wasm64. The exploratory branch is the seed for the same jump in icpp-pro.

Every capability, twice

Mock IC parity

ic0mock/ stubs 34 functions today. Each new binding is really binding + IC_API wrapper + mock implementation + test canister + docs, so native-mode debugging keeps working.

Plan

Suggested sequencing

  1. Repair the header ✓ done 2026-09-16

    Deleted the five dead funds declarations, unmangled ic0.h:84 (stable_size → ic0_stable_size), and fixed the mock's mismatched reject-msg declarations. Verified: clang-format, native builds + mock runs (canister_1 142/142, canister_timers 20/20), wasm build. Merged to main.

  2. New APIs: cycles, inspection, certified data ✓ done 2026-09-16

    Branch feature/ic0-step02: 13 imports bound — 128-bit cycles (incl. call_cycles_add128 bind+mock only), ingress inspection with a user-declared canister_inspect_message hook, and certified data. New entry-context guards on all new IC_API methods; new canister_inspect test canister; docs & demos on the same branch in icpp-docs / icpp-demos. Verified: all-static, native (canister_1 151/151, canister_inspect 7/7), full all-tests, upgrade test released→dev, docs build. Merged 2026-09-16: icpp-pro #53, icpp-demos #5 & icpp-docs #2 (CodeRabbit: 2 findings fixed, 2 rebutted & accepted as learnings).

  3. Existing APIs: context-guard retrofit

    Step 02a enforces the replica's permitted-entry-point matrix on all NEW IC_API methods. Retrofit the pre-existing wrappers (constructor reads, timers, …) the same way, audited per-function against the replica source (rs/embedders/…/system_api.rs) — its own compatibility assessment, trap tests, and upgrade-test run, because a mis-transcribed guard there would break working canisters.

  4. Breadth pass on introspection

    Caller info, system introspection, subnet & root key, environment variables, and cost estimation. Mechanically similar bindings; one pattern, ten wrappers.

  5. 64-bit stable memory

    Define a layout convention alongside ic-wasi-polyfill's stable-memory use, then expose stable64_* through IC_API.

  6. The async call API

    The big lift: a real inter-canister call model for C++ (issue #21). Composite queries and best-effort responses (call_with_best_effort_response, msg_deadline) then layer on top, along with the canister_on_low_wasm_memory export as an easy side quest. call_cycles_add128 is already bound & mocked; give it its IC_API home here.
